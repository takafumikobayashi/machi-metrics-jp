# 開発ルール

最終更新: 2026-08-29

## 1. 優先順位

判断が競合する場合は、次の順で優先します。

1. 統計の意味を誤らせない。
2. 原本から結果まで再現できる。
3. 利用者が主要な問いに短く到達できる。
4. 小さく実装・検証・公開できる。
5. 将来拡張できる。

拡張性のためにMVPを止める大規模な抽象化は行いません。反対に、基準日や分母のように後から直すと公開値の意味が変わる項目は先に固定します。

## 2. 文書を正本にする範囲

- プロダクトの目的: `CONCEPT.md`
- 初版の機能と完了条件: `MVP_SPEC.md`
- データの意味と計算: `DATA_SPEC.md`
- 技術境界: `ARCHITECTURE.md`
- 判断理由: `DECISIONS.md`

コードと文書が食い違う変更は未完了です。表記修正以外の仕様変更は、同じPull Requestで文書も変更します。

## 3. 実装ルール

- TypeScriptのstrict modeを維持する。
- データ境界ではランタイム検証を行い、型アサーションだけで通さない。
- 指標計算はI/OやUIから独立した純粋関数にする。
- 人数、率、日付を文字列に整形するのは表示層の直前だけにする。
- 浮動小数の表示丸めと計算精度を分離する。
- 自治体名で結合せず、5桁コードと時間キーを使う。
- 生成JSONや中間CSVを直接編集しない。
- UIコンポーネントから原本固有の列名を参照しない。
- コメントは「何をしているか」より、統計上・技術上の判断理由を残す。

## 4. データ追加の手順

新しい統計または年次データを追加する前に、次を決めます。

- 一次情報と具体的な配布表
- 利用条件と必要な出典表示
- 地理的粒度と自治体コード
- 基準日または集計期間
- 単位、分母、人口区分
- 欠損、秘匿、0の区別
- 既存系列との比較可能性
- 検証条件

その後、取得 → 正規化 → 検証 → 派生 → 公開を別ステップとして実装します。一つの巨大スクリプトで全処理を行わないでください。

## 5. テスト方針

### 必須

- 設定ファイルのスキーマと対象23市町
- 指標計算の通常値、0分母、欠損、境界値
- 類似度の標準化、重み、同距離時の安定した順序
- 公開JSONのスキーマ
- 対象期間とデータカバレッジ
- 主要ルートのビルド

### データ回帰

新リリースでは、前リリースとの自治体別差分を生成します。大きな変動を自動的に誤りと断定せず、原典に存在するか人が確認します。訂正値を受け入れる場合は理由をマニフェストに残します。

テスト用fixtureは実データ全量ではなく、定義上の難所を含む最小データにします。

## 6. アクセシビリティ

- セマンティックHTMLを優先する。
- クリック可能な`div`を作らない。
- フォーカス表示を消さない。
- グラフと地図に値の表または同等の代替を用意する。
- 色覚差と十分なコントラストを確認する。
- ツールチップだけに重要情報を置かない。
- 数字の読み上げ順と単位を確認する。

## 7. 表記

- 日付は曖昧な「2025年度」ではなく、原典に合わせて「2025年1月1日時点」「2024年中」などと書く。
- 率には分母を説明する。
- `+`/`-` と「増」「減」を組み合わせる。
- 1,000区切りを使い、単位を近接表示する。
- 全国順位は同率処理と候補集合を明示する。
- 統計から政策・原因を断定しない。
- 文字サイズはデジタル庁デザインシステムに準拠し、本文16px、補足14pxを下限とする。グラフのSVG軸ラベルだけは、年ラベルが横に収まらないため12pxを例外として許容する。
- フォントウェイトは400と700のみを使う。中間ウェイトは実体がなく合成太字になる。
- 和文に負の字間を使わない。字間は0か0.02emとする。
- サイズを下げて情報の主従を作らない。14pxで並ぶ値は太さと色で階層を示す。

## 8. Git運用

- 1変更はレビュー可能な大きさにする。
- コミットメッセージは変更の目的が分かる命令形または簡潔な説明にする。
- 自動生成物を含める場合、生成元も同じ変更に含める。
- 公開済みデータリリースを上書きしない。
- 秘密情報やローカルパスをコミットしない。

ブランチ戦略やコミット形式は、開発人数が増えるまで固定しません。

## 9. Definition of Done

変更は次を満たして完了です。

- 受け入れ条件を満たす。
- 新しい判断が文書化されている。
- データの出典と期間を追跡できる。
- 正常・欠損・エラー状態を確認している。
- `pnpm check` と `pnpm build` が成功する。
- 主要画面のモバイルとデスクトップ表示を確認している。
- 数値変更では少なくとも1自治体を原典と目視照合している。

## 10. ローカルコマンド

```bash
pnpm dev            # 開発サーバー
pnpm check          # format/lint/type/test/config検証
pnpm validate:data  # 人が管理するデータ設定の検証
pnpm build          # 本番ビルド
```

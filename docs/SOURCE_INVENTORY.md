## 6. 原本構造の確認結果

### `-03` 市区町村別人口・人口動態・世帯数

論理列は2016年・2025年で共通して次の25列です。

```text
団体コード、都道府県名、市区町村名、人口（男・女・計）、世帯数、
転入者数（国内・国外・計）、出生者数、その他記載数、住民票記載数計、
転出者数（国内・国外・計）、死亡者数、その他消除数、住民票消除数計、
増減数、増減率、自然増減数、自然増減率、社会増減数、社会増減率
```

確認した差分:

- 2016年は元号中心の見出しで、人口は平成28年、人口動態は平成27年として記載される。
- 2025年は元号見出しに加えて西暦年の行がある。
- 2016年ファイルは物理的な最大列数が257だが、論理的な非空ヘッダーは25列である。`max_column`だけを信頼せず、明示的な列仕様で読む。
- 年や項目名の固定行番号ではなく、見出しラベルとタイトルから基準年・集計期間を解釈する。

### `-04` 市区町村別年齢階級別人口

- 2016年・2025年とも、団体コード、都道府県名、市区町村名、性別、総数、0〜4歳から100歳以上までの5歳階級を持つ。
- 各自治体は原則として「計」「男」「女」の3行で構成される。
- 2016年の表題には、外国人住民の非公表や年齢不詳により階級合計と総数が一致しない場合がある旨の注記がある。
- 年齢階級の表記は`0～4歳`と`0歳～4歳`のように年によって差があるため、文字列完全一致ではなく下限・上限年齢へ正規化する。

## 7. 自治体コードの確認

原本の`団体コード`は6桁です。例えば広島市は`341002`です。正規化では次のように扱います。

```text
municipality_code = raw_code.slice(0, 5)
municipality_code6_raw = raw_code
```

2016〜2025年の全60ファイルについて、設定ファイルの広島県23市町すべてに対応する6桁コードを確認しました。町名は原本では「安芸郡府中町」のように郡名を含む場合があるため、名称では結合せずコードで結合します。

## 8. 拡張表の検算結果

拡張40原本について、次を機械検証しました。

- 各年・各表で広島県23市町の行が揃っている。
- `-03`の総人口と`-07`日本人住民人口＋`-11`外国人住民人口を突合し、10年×23市町で不一致0件。
- `-04`の年齢表総数と`-08`日本人住民年齢表総数＋`-12`外国人住民年齢表総数を突合し、10年×23市町で不一致0件。
- `-12`は安芸太田町で2016〜2020年が空欄、2021〜2023年が`X`となる非公表を確認した。総数は人口表と一致するため、年齢階級セルだけを秘匿値として扱う。

## 9. 正規化時の主キー

「団体コード＋年」を単独の主キーにはしません。

```text
人口・年齢構成:
  municipality_code + as_of_date

人口動態:
  municipality_code + period_start + period_end
```

原本参照には、少なくとも次の情報を持たせます。

```text
source_record_id = statistic_code + table_number + survey_year + raw_code + row_context
```

これにより、基準日人口と前年中の人口動態を混同せず、原本の行まで追跡できます。

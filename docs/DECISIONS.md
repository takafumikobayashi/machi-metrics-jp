## D-001: 広島県23市町を主役にする

- 日付: 2026-08-29
- 状態: accepted
- 判断: トップ画面とナビゲーションの中心を広島県23市町にする。全国データは主に比較対象の探索に使う。
- 理由: 全国を最初から同じ深さで見せるより、利用文脈を明確にしてMVPを小さくできる。一方、全国比較によって地域内ランキングだけでは得られない視点を保てる。
- 影響: 全国自治体の基礎データも処理するが、地図・編集コンテンツは広島を優先する。

## D-002: 住民基本台帳を年次人口の主系列にする

- 日付: 2026-08-29
- 状態: accepted
- 判断: MVPの人口推移は、総務省「住民基本台帳に基づく人口、人口動態及び世帯数調査」を主系列とする。
- 理由: 市区町村別の人口、年齢、自然動態、社会動態を毎年同じ枠組みで追える。5年ごとの国勢調査より、直近10年の動きに適する。
- 影響: 国勢調査や推計人口とは一つの折れ線に混在させない。

- 理由: 同じ年ラベルでも、時点人口と期間内イベントでは意味が異なる。誤った結合・表示を防ぐ。

## D-006: 公開サイトは事前生成JSONを読む

- 日付: 2026-08-29
- 状態: accepted
- 判断: e-Stat等への実行時問い合わせを行わず、取得・検証済みのバージョン付きJSONを配信する。
- 理由: 上流の可用性や形式変更から表示を隔離し、再現性、速度、キャッシュ性を得る。
- 影響: データ更新はアプリのデプロイとは分離可能なバッチ処理になる。

## D-007: MVPはTypeScript中心の単一ツールチェーンにする

- 日付: 2026-08-29
- 状態: accepted
- 判断: Webと初期データ処理をNode.js + TypeScriptで実装する。
- 理由: 初期実装・型共有・CIを単純にする。人口MVPの変換と距離計算はこの構成で十分な見込み。
- 再検討条件: Excel解析、地理処理、大規模集計で実装・性能・検証が著しく悪化した場合、データパイプラインだけPythonへ分離する。

## D-008: 類似度は説明可能な4特徴量で始める

- 日付: 2026-08-29
- 状態: accepted
- 判断: 対数人口、子ども比率、高齢者比率、10年人口増減率をロバスト標準化し、明示した重みで距離を計算する。
- 理由: 要望の3観点を満たしつつ、利用者が結果の理由を追える。生産年齢人口比率は3区分の合計制約で他2比率から決まるため、初版特徴量から外す。
- 影響: 「AIによる類似」とは呼ばず、計算式と各差分を公開する。

## D-009: 欠損値を推定補完しない

- 判断: MVPでは欠損を `null` とし、類似度の必須特徴量欠損は候補除外とする。
- 理由: 小規模な初版で推定値と公表値を混同するリスクを避ける。

## D-010: 元データと中間データはGit管理外、公開リリースは小さければ管理する

- 日付: 2026-08-29
- 状態: accepted
- 判断: `data/raw`, `staging`, `processed` はGit管理外とし、小規模な `public/data/releases` は再現性と簡易配信のためGit管理する。
- 理由: 大きな原本で履歴を膨らませず、表示に使った正確な成果物はコードと対応づけられる。
- 再検討条件: 公開成果物が単一10MBまたは合計100MBを継続的に超える場合、オブジェクトストレージ等へ移す。

## D-011: データリリースは不変にする

- 日付: 2026-08-29
- 状態: accepted
- 判断: `juki-2016-2025-v1` のようなIDで公開し、訂正は新IDを作る。`latest.json` のみ参照先を更新する。
- 理由: 過去の表示値を再現し、キャッシュと訂正履歴を安全に扱うため。

## D-012: 地図・チャートライブラリはデータ準備後に決める

- 日付: 2026-08-29
- 状態: accepted
- 判断: 初期環境では特定ライブラリを導入しない。
- 理由: 23市町の地図は単純SVGでも成立し、グラフは値表・読み上げ要件を含めて選ぶ必要がある。要件確定前の依存固定を避ける。
- 次の判断材料: GeoJSONサイズ、境界ライセンス、必要な操作、SSR対応、キーボード操作、バンドルサイズ。

## D-013: 指標計算は欠損と0分母でnullを返し、表示層で「データなし」と書く

- 日付: 2026-08-29
- 状態: accepted
- 判断: `src/lib/metrics` の指標関数は、欠損値または0分母で計算できない場合に例外ではなく `null` を返す。負の人口のような定義上ありえない入力は例外にする。表示層はその `null` を「データなし」と書き、0や空欄にしない。
- 理由: 欠損は原本に実在する正当な状態であり、1自治体・1指標の欠損で画面全体を落とすのは過剰。一方、負の人口は上流の検証漏れなので早期に失敗させたい。両者を戻り値の型で区別する。
- 影響: 指標の戻り値は `T | null` になり、UIは欠損分岐を必ず書くことになる。集計時に `null` を0として合算しない。

## D-015: Excel原本は一時CSVへ変換して解析する

- 日付: 2026-08-29
- 状態: accepted
- 判断: `.xls`と`.xlsx`の原本は変更せず、LibreOfficeの`soffice`で一時CSVへ変換し、同じCSVパーサーと表番号別の列定義で正規化する。
- 理由: 2016〜2020年は旧Excel形式、2021〜2025年は新Excel形式で配布されている。原表の結合セルや余分な書式列を除いた論理表を共通処理できる一方、`data/raw`の原本ハッシュは維持できる。
- 影響: データ処理を実行する環境にはLibreOfficeが必要。変換CSVは一時ディレクトリで処理後に削除し、stagingには原表由来の値だけを保存する。

## D-014: 比率は0〜1のまま保持し、百分率化と丸めを表示層に限定する

- 日付: 2026-08-29
- 状態: accepted
- 判断: 年齢構成比・増減率は内部で比率（0〜1）として保持する。`×100` と小数第1位への丸めは `src/lib/format` でのみ行う。増減の表記は符号と「増」「減」を併記し、丸めた後の値で符号を決める。
- 理由: 公開JSONと類似度計算で単位が二重定義になるのを防ぎ、丸め誤差を表示以外へ持ち込まない。`-0.04%` を「-0.0%減」と表示しないため、符号判定は丸めの後に行う必要がある。
- 影響: MVP_SPEC 4 の `× 100` は表示上の定義として読む。公開JSONに入る比率は0〜1。
- 単位の宣言: 指標IDは MVP_SPEC 4 の名称を変えず、比率であることを公開JSONのスキーマと `manifest.json` に書く。`_ratio` のような接尾辞をフィールド名に付けない。
- 補足: 2026-08-29にこの方針で確定。以後の変更は公開済みリリースの単位を変えるため、新リリースIDを必要とする（D-011）。

## D-015: ブランド色はテラコッタとし、公式サイトと誤認されない配色にする

- 日付: 2026-08-29
- 状態: accepted
- 判断: ブランド色を広島県の公式色（紫寄りの深紅）ではなくテラコッタ（`#c0532f` を基準）とし、色相をオレンジ側へ明確にずらす。ブランド色はヘッダー、ボタン、注記などUIのアクセントに限定し、グラフの系列色には使わない。
- 理由: 本サイトは公的統計を加工した非公式のプロジェクトであり、県の公式サイトと誤認されることは表示の正確さと同じくらい避けたいリスクである。色相を離すことで、免責文を読まなくても別物だと分かる。
- 影響: グラフは青・ティール・琥珀・紫の独立したカテゴリカル配色を使う。地図の階級区分にはテラコッタの単色シーケンシャルを充てる。

## D-016: 色は指標の意味にだけ使い、カードの識別には使わない

- 日付: 2026-08-29
- 状態: accepted
- 判断: 指標カードの色分け（枠線と数値の緑・橙・青）を廃止し、すべて同一のニュートラルにする。色を使うのは増減の方向（`--increase` / `--decrease`）と、グラフの系列区別だけとする。
- 理由: 色分けの結果、人口減少の値が「良い方向」を連想させる緑で表示されていた。カードの識別に色を使うと、色が意味を持つ場面で信頼できなくなる。
- 影響: 増減は引き続き符号と「増」「減」を併記し、色は補助にとどめる。装飾目的の英語ラベルと、押せそうに見えるだけのメニュー記号も同じ理由で廃止した。

## D-017: 順序のある区分には単色の濃淡を使う

- 日付: 2026-08-29
- 状態: accepted
- 判断: 年齢のように順序がある区分は、カテゴリカル配色ではなく単色シーケンシャル（`--age-1` 〜 `--age-4`）で表す。年齢が上がるほど濃く（ダークテーマでは明るく）する。
- 理由: 青・ティール・琥珀・紫のような順序のない4色では、区分の並び順が色から読み取れない。高彩度の面積が広くなり、総人口など本来重要な要素より目立ってしまう問題もあった。
- 影響: 色はトークンで定義し、コンポーネント側に直接書かない。テーマ切替に追従する。

## D-018: 独自の年齢区分は標準用語と区別し、年齢範囲を必ず併記する

- 日付: 2026-08-29
- 状態: accepted
- 判断: 画面表示用の4区分を「年少人口・若年層・壮年層・高齢者」と呼び、凡例と表に年齢範囲を併記する。「未成年相当」「現役世代」は使わない。
- 理由: 「未成年相当」は0〜14歳を指しており法律上の未成年（18歳未満）とずれる。「現役世代」は生産年齢人口（15〜64歳）と混同される。同じ言葉で別のものを指すと、統計の意味を誤らせる。
- 影響: 定義と3区分との関係を DATA_SPEC 7 に記載した。この4区分は指標として公開せず、画面表示に限る。

## D-019: タイポグラフィをデジタル庁デザインシステムに準拠させる

- 日付: 2026-08-29
- 状態: accepted
- 判断: 和文をNoto Sans JP（400/700）に固定し、文字サイズを5段階のトークンへ畳む。本文16px・補足14pxを下限とし、SVG軸ラベルの12pxだけを例外とする。負の字間は使わない。
- 理由: 10〜13pxの指定が42か所あり、高齢者比率を扱う住民向けの公的統計サイトとして体裁と内容が噛み合っていなかった。中間ウェイト（650・750・800）は実体がなく合成太字になり、輪郭が濁っていた。
- 影響: 指標カードと表の行が高くなり、情報密度は下がる。サイズ差で作っていた主従は、太さと色で作り直す（人口動態一覧の報告値と単純計算値など）。フォントはnext/fontがビルド時に取得してセルフホストするため、閲覧時の外部リクエストは発生しない。
- 未確認: 320〜390px幅での表示は、この環境でウィンドウを縮小できず未検証。実機またはデバイスエミュレーションでの確認が残っている。

## D-020: ティール系を系列色から外し、増加の意味色専用にする

- 日付: 2026-08-29
- 状態: accepted
- 判断: グラフの系列色からティール（旧 `--series-2`）を廃止し、社会増減と外国人住民を紫（`--series-4`）に移す。ティール系は増加を表す `--increase` だけに使う。
- 理由: 同じ画面に「社会増減の系列としてのティール」と「増加を意味するティール」が同居し、色の意味が二重化していた。系列色は増減の意味色と色相が重ならない範囲から選ぶ。
- 影響: 系列色は3色（青=人口のストック、琥珀=自然増減、紫=社会増減と外国人住民）になる。紫は詳細ページ内で2つの意味に使われるが、いずれも凡例つきの別カードであり、増減の意味色との衝突より弊害が小さいと判断した。

## D-021: パネルを分ける場合は色相で区分、明度で順序を示す

- 日付: 2026-08-29
- 状態: accepted
- 判断: 住民区分ごとにパネルを分ける年齢構成グラフでは、日本人住民を青の階調、外国人住民を紫の階調にする。凡例はパネルごとに持たせ、そのパネルの階調と一致させる。
- 理由: 見出しが紫で棒が青だと、見出しの色が何を指すのか読めない。色相で住民区分、明度で年齢の順序を示せば、パネル内の対応が一目で分かる（[[D-017]] の単色濃淡を住民区分ごとに用意する形）。
- 影響: 同じ年齢カテゴリがパネル間で別の色になるが、両パネルは人数の桁が異なり区分ごとの比較が主目的ではないため、パネル内の一貫性を優先する。凡例はカード共通ではなくパネル内に置く。
